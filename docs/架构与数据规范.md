# 休息一下 Take rest · 架构与数据规范（v0.2）

> 本文是实现契约：改代码前先确认与本文一致；改本文就同步改 README。

## 1. 产品定位

常驻 Windows 托盘的定时提醒器。按设定间隔在**任务栏正上方**弹出一个小文字条，提示用户做一个工位微动作（踮脚、蹬自行车、深呼吸、肩胛骨夹紧、坐着扭腰……），做完自动消失。

三条硬约束：

1. **订阅制扩展**：动作内容来自可订阅的包（GitHub 仓库 / 订阅源），软件本体只认数据格式，不硬编码动作。
2. **三级分类结构**：`类别 → 部位 → 幅度`，首版类别只有「身体」，首版幅度档位只有「静音」。
3. **任务栏自适应**：屏幕呈现不做固定坐标，必须自动识别任务栏在哪条边、多高，贴着它弹出来。

## 2. 四层架构

代码按职责切成四层，**依赖只能从上往下**，下层不许反向 require 上层：

```
┌─────────────────────────────────────────────┐
│ 1. electron 框架层   main / 窗口 / 托盘 / IPC │  只做「宿主」，不含业务
├─────────────────────────────────────────────┤
│ 2. 后台定时引擎      scheduler / timer        │  只回答「什么时候该提醒、提醒什么」
├─────────────────────────────────────────────┤
│ 3. 驱动桌面          desktop / taskbar        │  只回答「把东西放到屏幕哪里、怎么显示」
├─────────────────────────────────────────────┤
│ 4. 执行方式          executors/*              │  只回答「这次提醒用什么形式呈现」
└─────────────────────────────────────────────┘
```

### 2.1 各层职责与边界

| 层 | 目录 | 允许做什么 | 禁止做什么 |
|---|---|---|---|
| electron 框架 | `src/main/` | 单实例锁、创建窗口、托盘菜单、注册 IPC、生命周期 | 不算时间、不拼动作、不决定出现在屏幕哪里 |
| 后台定时引擎 | `src/engine/` | 计时、判断是否到点、按设置过滤动作、抽下一条、广播状态 | 不碰 BrowserWindow、不碰屏幕坐标 |
| 驱动桌面 | `src/desktop/` | 探测任务栏、算窗口几何、创建/定位/显示/隐藏承载窗口、点击穿透 | 不决定提醒内容、不读动作包 |
| 执行方式 | `src/executors/` | 拿到一次提醒载荷，决定渲染成什么、占多大、停多久 | 不自己定位窗口、不自己计时 |

### 2.2 执行方式注册契约

执行方式 = 一个实现了下面接口的模块，注册进**驱动桌面**，由驱动桌面按类型的优先级选中并呈现。

```js
/**
 * 执行方式接口（executor）
 * 驱动桌面通过 registerExecutor() 收录；检查顺序为 priority 高的优先。
 */
{
  type: 'text',                 // 唯一标识，写入动作包的 render.type
  label: '推送文字',             // 面板上给人看的名字
  priority: 100,                // 越高越先被选中

  /**
   * 这个执行方式能不能呈现这次提醒
   * @param {object} action 引擎抽出的动作（含 move / category / part / level）
   * @returns {boolean}
   */
  canHandle(action),

  /**
   * 渲染尺寸诉求：驱动桌面据此决定窗口大小与贴边方式
   * @param {object} action
   * @returns {{ mode:'bar'|'card'|'block', height:number, minWidth?:number }}
   */
  measure(action),

  /**
   * 生成给渲染进程的载荷。必须是可结构化克隆的纯 JSON。
   * @param {object} action
   * @param {{ seconds:number, showCountdown:boolean }} ctx
   * @returns {object}
   */
  payload(action, ctx),

  /**
   * 停留多少秒（驱动桌面据此收起）
   * @param {object} action
   * @param {object} settings
   * @returns {number}
   */
  duration(action, settings)
}
```

**注册方式**：`src/executors/index.js` 汇总内置执行方式并暴露 `list()`；驱动桌面初始化时对 `list()` 逐个 `registerExecutor()`。新增类型时只加一个文件 + 在 `index.js` 里追加一行，驱动桌面与引擎都不用改。

**当前已实现**：`text`（推送文字，默认，`priority: 100`）。
**预留（不实现）**：`image`、`video`、`progress` 等。图片类型接入时只需新增 `src/executors/image.js`，把 `measure()` 返回 `{mode:'card', height:160}` 之类，驱动桌面按 `mode` 换一种窗口形态，引擎零改动。

### 2.3 一次提醒的完整链路

```
engine.tick()                    // 2. 定时引擎：到点了吗？抽到哪条动作？
  → 得到 action { move, category, part, level }
desktop.dispatch(action, ctx)    // 3. 驱动桌面：挑执行方式、算几何、显示窗口
  → executor = registry.pick(action)     // 4. 按 priority 找 canHandle 为真的
  → { layout } = executor.measure(action)
  → bounds = computePopupBounds(taskbar, layout)
  → win.setBounds(bounds); win.showInactive()
  → win.webContents.send('executor:render', executor.payload(action, ctx))
  → 停留 executor.duration(action, settings) 秒后自动收起（看门狗兜底）
```

## 3. 技术栈

| 项 | 选择 | 理由 |
|---|---|---|
| 运行时 | Electron 30+（自带 Chromium） | 透明/无边框/置顶/点击穿透/多显示器/托盘，一套 Web 技术全拿到 |
| 主进程 | Node.js（Electron 内置），CommonJS | 分层模块之间用 CommonJS 明确依赖方向 |
| 渲染层 | React 18 + Ant Design 5 | 设置面板用 antd 组件；弹窗条极简，用裸 React |
| 构建 | Vite 5 + @vitejs/plugin-react 4 | 开发期 HMR；构建产物给 Electron 以文件方式加载 |
| 持久化 | JSON 文件（`%APPDATA%\<appName>\`，默认 `take-rest`） | 人和 AI 都能直接读改 |
| 订阅传输 | HTTPS 直连 GitHub raw / GitHub API | 不依赖 git 命令 |
| 打包 | `npm run build`（node 脚本 + Electron 自带 dist） | 不引入 electron-builder 之类的重依赖 |

**渲染层约定**：两个 React 入口（设置面板、提醒窗）共用一个 Vite 多页配置，产物落 `dist-renderer/`；Electron 开发期加载 dev server，打包后加载构建产物。**不要**在 Electron 主进程里 import React 相关包。

## 4. 数据规范 v1：动作包

一个动作包 = 一个 JSON 文件，可以被单独发布、被 GitHub 订阅。

```json
{
  "format": "gongwei-tixing-pack/1",
  "id": "gongwei-5lianhuan",
  "name": "工位“5连环”循环菜单",
  "version": "1.0.0",
  "author": "",
  "description": "每次循环大约 2-3 分钟",
  "source": "素材/工位五连环原始截图.jpg",
  "categories": [ /* 见下 */ ]
}
```

### 4.1 三级结构

```
category（类别）
└─ part（部位）
   └─ move（动作幅度档位）  ← 真正的动作条目，提醒抽的就是它
```

- **category** 首版只有 `身体`。字段：`id`(slug)、`name`、`order`、`parts[]`。
- **part** 部位，如「小腿」「腹部」「腰背」「颈肩」。字段：`id`、`name`、`order`、`moves[]`。
- **move** 动作，**`level` 就是幅度档位，首版只有 `静音`**。字段见下表。

```json
{
  "id": "sit-calf-raise",
  "level": "静音",
  "name": "坐姿踮脚",
  "order": 1,
  "prompt": "坐姿踮脚 · 双脚平踩，用力踮起脚尖，停 2 秒再重重放下 · 连做 20 个",
  "detail": "打游戏/上班久坐，血液都在小腿，踮脚能把血泵回心脏",
  "dosage": "连续做 20 个",
  "durationSec": 40,
  "tags": ["下肢泵血", "防腿粗"]
}
```

字段定义：

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | 是 | string，全局唯一（跨包也要唯一） | 建议 `部位-id` 前缀，如 `ab-bicycle` |
| `level` | 是 | enum：`静音` \| `轻响` \| `震动` | 幅度档位。首版只填 `静音` |
| `name` | 是 | string | 动作名，弹窗大标题 |
| `order` | 否 | number | 同部位内排序 |
| `phases` | 否（有则优先） | `[{ text, sec }]` | **分段时间轴**：把动作拆成最小步骤，每步一段。见下方「分段动作」 |
| `transitionSec` | 否 | number | 段与段之间的切换留白，默认 2 秒 |
| `reps` | 否 | number | 重复次数。**不写进正文**，只体现在提醒条底部的 `1/4` 计数 |
| `prompt` | 有 `phases` 时可省 | string | 简单动作的整行文字；有 `phases` 时由各段自动生成，无需手写 |
| `detail` | 否 | string | 补充说明，面板里展示 |
| `dosage` | 否 | string | 剂量原文，如「连做 20 个」 |
| `durationSec` | 否 | number | 建议占用时长。分段动作应等于 `（各段之和 + 段间切换）× reps` |
| `tags` | 否 | string[] | 作用/关键词 |

**分段动作（`phases`）** — 推荐写法

```json
{
  "id": "light-breath-4-6",
  "level": "静音",
  "name": "4-6 呼吸",
  "phases": [
    { "text": "深呼吸", "sec": 6 },
    { "text": "吐气", "sec": 4 }
  ],
  "transitionSec": 2,
  "reps": 4
}
```

- **一次流程**（一轮）= 各段秒数之和 + 段间切换 = `6 + 4 + 1×2 = 12 秒`
- **总时长** = 一轮 × 次数 = `12 × 4 = 48 秒`
- **正文自动生成**为 `深呼吸 6秒 · 吐气 4秒`——**不写「重复 4 次」**，重复只体现在右下角的 `1/4`
- **颜色按段切换**：红橙黄绿青蓝紫的浅色系，第 n 段取第 n 个颜色，圆点、段内进度条、当前段文字同步用这个色
- 当前段文字上色加粗，其它段压暗，一眼能看出现在该做哪一段
- `sec` 必须是正整数；0 或负数的段会被丢弃（不是夹成 1 秒）

**幅度档位语义（重要，首版只实现 `静音` 的呈现，但数据结构要预留）**：

- `静音`：无声，纯文字条，靠视觉提醒。弹窗 100% 透明背景上只有一行字。
- `轻响`：预留，弹出时伴随轻微提示音 + 文字。
- `震动`：预留，弹出时窗口轻微抖动 / 闪烁。

数据处理规则：`level` 必须是三者之一，缺省补 `静音`；未知 level 视为非法，整条 move 丢弃并记日志。

## 5. 弹窗呈现规范（自动贴合任务栏）

### 5.1 任务栏探测算法（`taskbar.js`）

只做一件事：返回一个对象

```js
{ edge: 'bottom'|'top'|'left'|'right', thickness: 48, workArea: {x,y,width,height}, screen: {x,y,width,height} }
```

判定方式（按顺序）：

1. Windows 任务栏通常**吸附在屏幕边缘**且**不包含在工作区**（`screen.workArea`）。对四条边分别算「屏幕框 - 工作区」的差值厚度：`bottom = screen.bottom - workArea.bottom` 等。
2. 差值 > 0 的那条边就是任务栏所在边；`thickness` = 该差值。
3. 若四条边差值都 ≤ 0（任务栏自动隐藏 / 工作区被别的东西占用），走**兜底**：`edge='bottom'`，`thickness=48`（系统默认值），并把弹窗位置再往屏幕内缩 12px，避免被遮。

> 实现细节：Electron 主进程可用 `screen.getPrimaryDisplay().workArea` / `.bounds`。要处理**多显示器**：弹窗出现在「鼠标所在的那块屏」上，用 `screen.getDisplayNearestPoint(screen.getCursorScreenPoint())`。

### 5.2 弹窗几何规则

有两条路径，由执行方式的 `measure()` 决定走哪条：

**A. 铺满横条**（`measure()` 不带 `fit`）：高度固定 `H = 44`，左右留白 `M = 24`，贴合间距 `G = 8`。

- `edge='bottom'`：`x = workArea.x + M`，`width = workArea.width - 2M`，`y = workArea.y + workArea.height - H - G`。
- `edge='top'`：`y = workArea.y + G`。

**B. 居中自适应**（`measure()` 返回 `fit: true`，当前 `text` 执行方式走这条）：

- 宽度由内容决定：先量「不换行时需要多宽」，夹到 `[minWidth=240, workArea.width × maxWidthRatio(=0.5)]`。
- **水平居中**：`x = workArea.x + (workArea.width - width) / 2`。
- 宽度顶到上限后**文字换行**，高度随行数自动增加（不再截断成省略号）。
- 高度由渲染层量出来回报：提醒窗渲染完 → `popup:resize` → 驱动桌面 `resizeTo()` 重排。

公共部分：

- `edge='left'` / `'right'`：退化为竖向窄条，宽度 `= thickness * 4`，高度 `= workArea.height - 2M`。
- 窗口：`frame:false, transparent:true, resizable:false, alwaysOnTop:true, skipTaskbar:true, focusable:false, hasShadow:false` + `setIgnoreMouseEvents(true)`（点击穿透，不抢焦点）。
- `alwaysOnTop` 层级用 `'screen-saver'` 以上不行就用 `'floating'`；显示前 `showInactive()`。

### 5.3 视觉

- 深色圆角条，底色 `rgba(18,20,24,0.92)`，圆角 10px，边框 `1px rgba(255,255,255,0.10)`。
- 左侧一个小色块（`#4ade80`）呼吸动画表示「该动了」；右侧 `剩余 28s` 倒计时数字。
- 文字：`15px / 1.45`，白色 92%，**允许换行**（`overflow-wrap:anywhere`）；顶到最大宽度就换行，高度自动增加。
- **分段动作**（`move.phases` 存在）：正文是各段的 `深呼吸 6秒 · 吐气 4秒`，当前段用它的浅色高亮、其余压暗；下方一行是**当前段内**的进度条 + `1/4` 计数。段与段之间留 `transitionSec`（默认 2 秒）切换时间，切换期间颜色已经切到下一段。
- **简单动作**（没有 `phases`）：只有正文和倒计时；包里有 `reps` 时才显示整体进度条与 `3/20`。
- 入场：`translateY(8px) → 0` + `opacity 0 → 1`，180ms。退场反相，120ms 后窗口 `hide()`。

## 6. IPC 契约（主进程 ↔ 面板）

通道名一旦定死，两侧都按这个写。**（v0.1 实施时的最终名字以本表为准）**

| 通道 | 方向 | 载荷 | 返回 |
|---|---|---|---|
| `state:get` | 面板 → 主 | 无 | `{ settings, packs, actionCount, nextFireAt }`；`packs[i]` 含 `id/name/source/count/categoryCount/origin/enabled/categories`，**`categories` 是面板渲染三级树的唯一来源** |
| `settings:set` | 面板 → 主 | 部分 settings 对象 | 完整 settings |
| `scheduler:next` | 面板 → 主 | 无 | `{ move, pack, path, category, part, level }` 预览下一条 |
| `scheduler:fire` | 面板 → 主 | 无 | 立刻弹一次（试看） |
| `packs:list` | 面板 → 主 | 无 | 轻量摘要 `[{ id, name, source, count, categoryCount, origin, enabled }]`，**不含 categories** |
| `packs:toggle` | 面板 → 主 | `{ id, enabled }` | 最新 packs 列表 |
| `subscription:status` | 面板 → 主 | 无 | `{ sources, lastSyncAt, lastSyncError }` |
| `gh:request` | 面板 → 主 | `{ url }` | `{ ok, status, body, error }`，主进程发 HTTPS（渲染进程 fetch 会撞 CORS） |
| `subscriptions:install` | 面板 → 主 | `{ name, source, packs }` | 落盘并刷新索引 |
| `subscriptions:sync` | 面板 → 主 | `{ source }`（空 = 全部） | `{ ok, source, packCount, error }` |
| `settings:changed` | 主 → 面板 | settings | 广播，面板刷新 UI |
| `packs:changed` | 主 → 面板 | packs 摘要 | 广播 |
| `popup:show` / `popup:hide` | 主 → 弹窗 | 见 §5 | |
| `popup:done` / `popup:ready` | 弹窗 → 主 | 无 | |

> 主进程对 `subscriptions:*` 与 `gh:request` 另注册了单数别名（`subscription:install` / `subscription:sync` / `ipc:gh:request`）指向同一 handler，两种写法都能通。

`settings` 结构：

```js
{
  intervalMin: 20,        // 提醒间隔（分钟）
  enabled: true,          // 总开关
  popupSeconds: 0,        // 弹出后停留秒数；0 表示用每个动作自己的 durationSec
  categories: { "身体": true },   // 粗粒度：整类参与/不参与
  levels: { "静音": true },       // 粗粒度：按档位名全局开关（老字段，面板已不再用它做勾选）
  disabledPaths: [],      // 细粒度：形如 "身体/小腿/静音"，同一档位在不同部位下互不影响
  activePackIds: ["gongwei-5lianhuan", "office-light"], // 启用的动作包；内置两个默认都开
  shuffle: false,         // false = 按 order 循环走；true = 随机
  activeHours: { start: 9, end: 20 }, // 只在这段时间提醒（整点），两边留空 = 全天
  showCountdown: true,
  // 提醒条外观（面板「样式」tab）
  appearance: {
    minWidth: 240,        // 默认（最小）宽度 px
    maxWidth: 1280,       // 最大宽度 px；实际还会被屏宽 80% 夹一次
    fontSize: 15,         // 文字大小 px（10–32）
    align: 'center',      // 文字对齐 left / center / right
    textColor: '#ffffff', // 文字颜色（只接受 #rgb / #rrggbb）
    textOpacity: 0.92,    // 文字透明度 0.1–1
    bgOpacity: 0.92,      // 背景透明度 0.1–1
    screen: 'cursor',     // 显示的屏幕 cursor（鼠标所在）/ primary（主屏）
    position: 'bottom',   // 展示位置 bottom（任务栏上方）/ top / center
    theme: 'dark'         // 背景深浅 dark / light
  }
}
```

`disabledPaths` 是当前面板上「启用」勾选框真正写的东西：取消勾选某个部位下的档位，只往这里追加一条路径，不会牵连别的部位。`categories` / `levels` 保留为粗粒度兜底（老设置文件里可能还有），三者是「与」的关系——任何一个说不，这条动作就不参与抽取。

`appearance` 每项在主进程 `normalizeSettings` 里都有取值域校验，非法值一律回落默认：字号 10–32、透明度 0.1–1、颜色必须是 `#rgb`/`#rrggbb`、`maxWidth` 不会小于 `minWidth`。`screen` / `position` / `theme` / `align` 是枚举，非法值回默认。

面板是「侧边栏 + 三 tab」结构：**主页**（状态概览、动作包列表、快捷操作）、**动作**（节奏 + 动作包勾选 + 订阅）、**样式**（上面这 10 项外观）。

## 7. 订阅机制规范

订阅源 = 一个可以直接 `GET` 到 JSON 的 URL（GitHub raw 链接）或一个 GitHub 仓库（含 `manifest.json` 指明包列表）。同步实现额外支持 `file://`，便于本地验证。

```json
{
  "format": "gongwei-tixing-registry/1",
  "name": "我的提醒动作",
  "description": "可选",
  "packs": [
    "packs/工位五连环.json"
  ]
}
```

添加流程（面板 `gh.js` 负责，主进程只负责落盘和刷新）：

1. 用户粘贴 GitHub 仓库 URL（如 `https://github.com/yuanxin518/take-rest`）→ 拼成 `https://raw.githubusercontent.com/{owner}/{repo}/HEAD/manifest.json`（失败依次回退 `main` / `master`）。
2. **跨分支查找**：仓库约定是「默认分支放代码、单独一个分支放动作包」，所以默认分支没有 `manifest.json` 属正常。前三步全失败时，用 GitHub API `GET /repos/{owner}/{repo}/branches?per_page=100` 列出分支逐个找；API 不可用再退回常见分支名（`packs` / `data` / `actions`）。命中的分支写进动作包 `branch` 字段，面板提示「动作包分支：packs」，订阅源地址记成该分支的 raw 地址。
3. 拉取 manifest → 逐个拉取 packs → 交给主进程 `subscriptions:install` 写入 `<数据目录>\subscriptions\{源名}\`（源名优先取 manifest 的 `name`）。主进程的 `syncSource` 走同一套 locateManifest 逻辑，保证「添加」和「同步」行为一致。
4. 每 6 小时自动同步一次；失败保留旧缓存并在面板显示错误，**绝不能因为同步失败而清空已有动作**。
5. 订阅里拿到的 move 若 `id` 与本地的撞车，订阅版本覆盖本地版本（订阅是权威源），并记日志。

**传输层**：`ghFetchText` 先直连（6 秒超时），失败自动回退到系统代理（`HTTPS_PROXY` 等环境变量 → Windows 注册表 `ProxyServer`），走 HTTP CONNECT 隧道 + TLS。直连失败后 90 秒内的后续请求直接走代理，避免一次订阅里每条请求都等满超时。全程零第三方依赖。两个原因都写进错误文案。

加载顺序固定：**内置 `src/packs/` → 用户 `packs/` → 订阅 `subscriptions/`**，同名 id 后者覆盖前者。内置包无条件加载，不受用户数据目录影响。

沙箱限制：渲染进程直接 `fetch` 会撞 CORS。**统一走主进程 `ipc:gh:request` 发 HTTPS 请求**，不放宽 `webSecurity`。
