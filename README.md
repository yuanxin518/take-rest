# 休息一下 Take rest（take-rest）

定时在**任务栏正上方**弹一条文字的桌面小工具，提醒你在工位上做一个微动作：踮脚、蹬自行车、深呼吸、夹肩胛骨、扭腰。动作内容不写死在程序里，靠 **GitHub 订阅**扩展。

- 运行平台：Windows 10 / 11（Electron 30，托盘常驻）
- 界面：React 18 + Ant Design 5（Vite 构建）
- 动作数据结构：`类别 → 部位 → 幅度档位 → 动作`，首版类别 = `身体`，幅度 = `静音`
- 架构：`electron 框架 → 后台定时引擎 → 驱动桌面 → 执行方式` 四层，当前只有 `text`（推送文字）一种执行方式
- 当前版本：v0.2.0

---

## 一、先把项目拉下来跑起来

```powershell
git clone https://github.com/yuanxin518/take-rest.git
cd take-rest
npm install
npm start
```

两条命令的区别：

| 命令 | 做什么 | 什么时候用 |
|---|---|---|
| `npm start` | 先 `vite build` 出 `dist-renderer/`，再启动 Electron | 日常使用 |
| `npm run dev` | 起 Vite dev server（带热更新）再启动 Electron | 改界面时，保存即生效 |

`npm start` 之后：

1. 托盘出现一个小圆点图标，**首次启动自动打开设置面板**。
2. 默认 **每 20 分钟**提醒一次，只在 **09:00–20:00** 提醒。
3. 提醒条出现在任务栏正上方，**点击穿透**（鼠标点它等于点在下面的窗口上），不抢焦点。
4. 倒计时走完自动收起；设置里可关掉倒计时数字。

> **如果你看到 `Cannot read properties of undefined (reading 'requestSingleInstanceLock')`**
> 说明环境里有 `ELECTRON_RUN_AS_NODE=1`（某些 IDE / 终端会设），此时 `electron` 会退化成纯 Node 进程。
> 清掉再启动即可：
> ```powershell
> Remove-Item Env:ELECTRON_RUN_AS_NODE
> npm start
> ```

> 没有装 Node 的机器可以只跑二进制，但本项目暂未提供安装包（见[后续规划](#九后续规划)）。

## 二、软件长什么样

### 提醒条（贴在任务栏上方）

**普通动作**（只有文字 + 倒计时）：

```
●  坐姿踮脚 · 脚平踩用力踮脚尖，停 2 秒重重放下 · 连做 20 个            剩余 39s
```

**带次数的动作**（动作包写了 `reps`，下方多一条进度和计数）：

```
●  4-6 呼吸 · 鼻吸 4 秒、嘴呼 6 秒，肩膀别耸 · 做 6 次                  剩余 59s
   ████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░      3/6
```

- 深色圆角条，左侧绿点呼吸。
- **宽度不再铺满全宽**：条宽由内容决定、**水平居中**，最大占屏宽约一半（2560 的屏最宽 1280）。
- **顶到最大宽度就换行，高度自动增加**，不再用省略号截断长口令。
- **自动识别任务栏位置**：任务栏在下就贴上方、在上就贴下方、在左/右退化成竖向窄条。判定方式是「屏幕范围 − 工作区范围」的差值为哪条边。
- 多显示器：出现在鼠标所在的那块屏。
- 任务栏设为自动隐藏时，走兜底（贴底 + 内缩 12px），不会跑到屏幕外面。

### 设置面板

React + Ant Design，**左侧边栏 + 三个 tab**（侧边栏顶部是品牌，底部是总开关与一句摘要）：

**主页** — 概览与快捷操作
- 四宫格：提醒开关、提醒间隔、下次提醒、动作条数
- 动作包列表（名称 / 条数 / 内置·订阅·本地）
- 「试看下一条」「立刻提醒一次」，以及跳到「动作」「样式」的入口

**动作** — 节奏与动作源
- 提醒间隔：数字输入 + 10 / 20 / 30 / 45 / 60 分钟胶囊快捷
- 弹出停留：`自动`（跟随动作自带时长）/ 5 秒 / 8 秒 / 12 秒胶囊，也可填任意秒数
- 随机顺序、显示倒计时：方形勾选框
- 生效时间段：两个整点数字框，「都留空 = 全天」
- `身体 → 部位 → 幅度档位 → 动作` 三级折叠树：
  - **默认全部收起**，进来先看到动作包和类别，需要时再展开
  - 每个部位下的「启用」**各管各的**：关掉「小腿 · 静音」不会影响「腹部 · 静音」
  - 取消勾选类别，它下面整枝置灰、不参与抽取
- 订阅：粘贴 GitHub 仓库地址、立即同步、本地导入 JSON；订阅源持久化，输入框记住最后一次粘的地址

**样式** — 提醒条长什么样、出现在哪
- 默认宽度（最小宽度）、最大宽度（px，实际不超过屏幕 80%）
- 文字大小（10–32px）、文字对齐（左 / 中 / 右）
- 文字颜色、文字透明度（倒计时会再淡一档）、背景透明度、背景深浅
- 显示的屏幕（鼠标所在屏 / 主屏）、展示位置（贴任务栏上方 / 屏幕顶部 / 垂直居中）

改完立刻生效，点「试看下一条」即可看到效果。

界面效果见 [交付截图/产品设计图-主图.jpg](交付截图/产品设计图-主图.jpg)（设计稿）与 `交付截图/新界面-*.png`（实机）。

## 三、动作数据结构

一个动作包 = 一个 JSON。完整字段见 [docs/架构与数据规范.md](docs/架构与数据规范.md) 第 4 节。

```
category 类别（身体）
└─ part 部位（小腿 / 腹部 / 颈肩背 / 腰腹）
   └─ move 动作，level = 幅度档位（静音）
```

`level` 语义：`静音` = 无声纯文字（首版实现）；`轻响`、`震动` 预留，见[规划](#九后续规划)。

`reps` 可选：写了就是「按次数做」的动作，提醒条下方会显示进度条和 `3/20`；不写就只有文字与倒计时。

内置两个动作包。**所有动作都按最小步骤拆开**：每一步是一段 `phases`（文案 + 秒数），段与段之间留 2 秒切换时间，重复次数只体现在提醒条右下角的 `1/4` 里，不写进正文。

**[src/packs/工位五连环.json](src/packs/工位五连环.json)** — 5 个需要起身/大幅度做的工位动作：

| 部位 | 动作 | 分段 | 一轮 / 次数 | 总时长 |
|---|---|---|---|---|
| 小腿 | 坐姿踮脚 | 踮起脚尖 2s + 停住 2s + 放下 1s | 9s × 6 | 54s |
| 腹部 | 坐姿蹬自行车 | 左腿前蹬 3s + 右腿前蹬 3s | 8s × 5 | 40s |
| 腹部 | 腹式深呼吸 | 吸气鼓肚子 4s + 呼气微收腹 6s | 12s × 4 | 48s |
| 颈肩背 | 肩胛骨夹紧 | 肩胛后夹 3s + 放松 3s | 8s × 6 | 48s |
| 腰腹 | 坐着扭腰 | 向左侧扭 3s + 向右侧扭 3s | 8s × 5 | 40s |

**[src/packs/办公室轻动作.json](src/packs/办公室轻动作.json)** — 10 个**不用起身、幅度很小**的动作，适合开会、有人在场、穿正装：

| 部位 | 动作 | 分段 | 一轮 / 次数 | 总时长 |
|---|---|---|---|---|
| 呼吸 | 4-6 呼吸 | 深呼吸 6s + 吐气 4s | 12s × 4 | 48s |
| 呼吸 | 腹式呼吸 | 吸气鼓腹 4s + 呼气收腹 6s | 12s × 5 | 60s |
| 呼吸 | 叹气式放松 | 吸满 3s + 张嘴叹气 5s | 10s × 3 | 30s |
| 微微发力 | 坐姿收腹 | 收紧 10s + 放松 5s | 17s × 4 | 68s |
| 微微发力 | 大腿轻压 | 顶住发力 8s + 松开 4s | 14s × 4 | 56s |
| 微微发力 | 臀肌轻夹 | 夹紧 5s + 放松 5s | 12s × 5 | 60s |
| 手部活动 | 张指松手 | 张开五指 3s + 轻握拳 3s | 8s × 8 | 64s |
| 手部活动 | 转手腕 | 向左转圈 8s + 向右转圈 8s | 18s × 3 | 54s |
| 手部活动 | 压掌拉伸 | 左手压掌 10s + 右手压掌 10s | 22s × 3 | 66s |
| 手部活动 | 拇指松解 | 揉左手拇指根 10s + 揉右手拇指根 10s | 22s × 2 | 44s |

「4-6 呼吸」弹出时是这样：

```
●  深呼吸 6秒 · 吐气 4秒                          剩余 47s
   ████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░        1/4
```

- 当前段**深呼吸**用浅红色高亮，其它段压暗；进入吐气时整体切成浅橙色
- 进度条是**当前段内**的进度，颜色跟着段走
- 右下角 `1/4` 是第 1 次 / 共 4 次——**正文里不出现「重复 4 次」**

颜色按段序循环取浅色版的红橙黄绿青蓝紫（`#ffb4b4` `#ffd2a8` `#ffeaa0` `#b8ecc4` `#a8e6e0` `#b4d4ff` `#d7bcff`）。

> 订阅仓库的 `packs` 分支里还有第三个包 **加练-站立版**（5 条，同一套动作改成站着做），已经和这两个内置包一样改成 phases 结构。订阅后一共 20 条动作。

**所有动作都是「进度 + 次数」形态**：没有「做 10 次」「左右各 5 圈」这类写在正文里的剂量了，次数统一由右下角的 `1/N` 表达，正文只写「这一步做什么 + 这一步几秒」。

## 四、GitHub 订阅

### 仓库按「代码 / 数据」分两个分支

| 分支 | 放什么 |
|---|---|
| `main` | 软件代码 |
| `packs` | 动作包订阅源：`manifest.json` + `packs/*.json` |

想给自己加动作，只要有一个带 `manifest.json` 的公开仓库就行，用哪个分支都没关系——**软件会自己找**。

### 怎么订阅

在设置面板 →「订阅」里粘贴地址：

| 订阅内容 | 粘贴 |
|---|---|
| 仓库地址（自动找到放动作包的分支） | `https://github.com/yuanxin518/take-rest` |
| 锁定某个分支的 raw 地址（推荐，地址不会随默认分支变） | `https://raw.githubusercontent.com/yuanxin518/take-rest/packs/manifest.json` |

粘仓库地址时，默认分支上没有 `manifest.json` 是正常的——软件会先试 `HEAD / main / master`，失败后用 GitHub API 列出所有分支逐个找，找到后绑定并提示「动作包分支：packs」。API 拿不到时还会退回常见分支名（`packs` / `data` / `actions`）再试一轮。

### 自己建一个订阅源

最小结构：

```
manifest.json
packs/我的动作.json
```

```json
{
  "format": "gongwei-tixing-registry/1",
  "name": "我的提醒动作",
  "packs": ["packs/我的动作.json"]
}
```

推到公开仓库，把仓库地址粘进面板即可。动作包格式见[第三节](#三动作数据结构)与 `docs/架构与数据规范.md`；本仓库的 [订阅仓库模板/](订阅仓库模板/) 是一份可直接复制的样例。

### 网络：直连不行会自动走代理

在部分网络环境下 `raw.githubusercontent.com` 直连时好时坏、`github.com` 的 git 通道可能被阻断。软件的策略是：**先直连（6 秒超时），失败自动改用系统代理重试**；直连失败后的 90 秒内，后续请求直接走代理，不再一条条等超时。代理来源按顺序：

1. 环境变量 `HTTPS_PROXY` / `https_proxy` / `HTTP_PROXY` / `http_proxy`
2. Windows 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` 的 `ProxyServer`（`ProxyEnable=0` 也当弱候选，因为开着端口但没勾选「使用系统代理」是常见状态）

日志会写：`[提醒] 直连失败（ETIMEDOUT），改用系统代理 127.0.0.1:7890 重试`。两边都失败时，报错里会同时列出两个原因。

如果 `git clone` / `git push` 也不通，只影响你自己推代码，不影响软件运行；需要时单独给 git 配代理：

```powershell
git config --global http.proxy http://127.0.0.1:7890
```

## 五、数据存在哪

`npm start` 运行时数据写在用户目录，**不在项目目录里**：

```
%APPDATA%\take-rest\
├─ settings.json                  设置
├─ packs\                         用户自己放的本地动作包
└─ subscriptions\
   ├─ subscriptions.json          订阅源清单、上次同步时间、上次错误
   └─ <源名>\                      每个订阅源同步下来的包
```

内置包在程序目录 `src/packs\`，永远参与加载，不受上面目录影响。

环境变量 `DESK_REMINDER_DATA_DIR` 可覆盖数据根目录（自检脚本用它隔离环境）。

## 六、代码结构

按四层切分，依赖只能从上往下：

```
renderer/            React 18 + antd 5（Vite 构建，产物 dist-renderer/）
├─ panel/            设置面板（components/TitleBar.jsx 是自定义标题栏）
│  ├─ components/    标题栏
│  ├─ sections/      主页 / 节奏 / 动作树 / 订阅 / 样式
│  └─ preload.cjs    面板 IPC 桥（含窗口控制）
├─ popup/            提醒窗（按 payload.type 分发到 executors/）
│  └─ executors/     每种呈现形式一个组件（text.jsx）
└─ shared/           gh.js（订阅解析）、format.js

assets/              应用图标（由 scripts/make-icon.py 生成）
├─ icon.ico          Windows 多尺寸图标
├─ icon.png          1024 满幅方形
├─ icon-rounded.png  1024 圆角透明
└─ icons/            16~512 各尺寸 PNG（≤32 为简化绘制）

src/                 主进程（CommonJS）
├─ main/             1. electron 框架层：入口 / 窗口 / 托盘 / IPC
├─ engine/           2. 后台定时引擎：计时、抽动作（不碰窗口）
├─ desktop/          3. 驱动桌面：任务栏几何、窗口生命周期、执行方式注册表
├─ executors/        4. 执行方式：text.js（+ index.js 汇总清单）
├─ subscriptions.js  订阅传输（直连 → 系统代理回退）
└─ packs/            内置动作包
```

**新增一种呈现形式**（比如图片、跑马灯）要动的地方是固定的三处：`src/executors/` 加一个实现契约的模块、`src/executors/index.js` 追加到清单、`renderer/popup/executors/` 加一个只画正文区的组件。引擎与驱动桌面都不用改。

### 图标与窗口标题栏

应用图标是「计时环 + 1min」：深炭灰圆角底、薄荷绿环形刻度、中间 `1min`。原图在 `build/icon-raw-2.jpg`，跑

```powershell
python scripts/make-icon.py
```

会生成 `assets/` 下的全部尺寸。小尺寸（16/24/32）是脚本单独绘制的简化版（只留环 + 加粗的 1），因为把 1024 直接缩到 16px 字会糊成一团。

面板窗口用 `frame: false`，**标题栏是自绘的**：`renderer/panel/components/TitleBar.jsx` 负责图标、标题和最小化 / 最大化 / 关闭三个按钮，空白处可拖动窗口（`-webkit-app-region: drag`）。按钮通过 `window:minimize` / `window:toggleMaximize` / `window:close` / `window:isMaximized` 四个 IPC 通道调主进程。

> 打包产物的 `take-rest.exe` 本身还是 Electron 默认图标——改 exe 的 PE 资源需要 rcedit 之类的工具，目前没引入。托盘和任务栏显示的已经是新图标。

细节见 [docs/架构与数据规范.md](docs/架构与数据规范.md) 第 2 节。

## 七、自检

```powershell
npm run smoke                                   # 数据结构 + 语法 + 四层依赖边界
npm run check                                   # 端到端（会真的启动应用、弹窗、截图）
npm run build                                   # 打包成 dist/take-rest-<platform>-<arch>/
```

`npm run smoke` 除了查数据与语法，还会校验分层没被破坏：引擎层不许碰 `BrowserWindow` / `ipcMain` / 屏幕，驱动桌面不许直接依赖引擎业务，执行方式不许碰 electron。

`npm run check` 验证：内置包加载、订阅同步、外网连通、执行方式分发、真实动作弹窗、弹窗位置与任务栏算法一致、面板能加载；截图写到 `.smoke-data\shots\`（该目录已在 `.gitignore` 里）。

## 八、已知边界

- 订阅只支持公开仓库，不支持 token / 私有库。
- 勾选粒度到「类别」和「某个部位下的档位」；单条动作还不能单独开关。
- 次数进度是**按时间推进**的估算（时间过多少、进度走多少），不是真的检测你做了几个。
- 没有开机自启、没有安装包（`electron-builder` 未接）。
- 幅度档位 `轻响` / `震动` 只定义了语义，程序里尚未实现对应表现。
- 面板窗口固定大小，不记忆上次位置。

## 九、后续规划

现在的形态是**被动**的：到点弹一条，弹完就没。接下来要长出来的能力，是让动作包变成一个**随时可调取的提示库**——典型的落地场景是游戏 / 直播 / 剪辑里的 tips 提示：需要的时候立刻甩一条出来，不需要的时候安安静静躺着。

四条方向，前三条是「即时调取」，第四条是「感知当前内容再调取」。

### 8.1 即时调取：关键词触发、快捷键翻页、滚动播报

| 能力 | 想要的体验 | 打算怎么接 |
|---|---|---|
| **关键词触发** | 说一句 / 打一句关键词（如「喝水」「护眼」「揉肩」），立刻从**已订阅的全部动作包**里命中相关条目并马上显示，不等定时器 | 引擎层加一个 `trigger` 入口：关键词 → 在 `move` 的 `name` / `tags` / `prompt` 上做匹配 → 命中即 `desktop.dispatch()`。多个包都命中时按匹配度排序，取第一条；同分随机，避免每次都是同一条 |
| **快捷键翻页** | 全局快捷键（如 `Ctrl+Alt+→` / `←`）在当前包里手动上下翻，翻到哪条立刻显示哪条 | 框架层用 `globalShortcut` 注册，回调转给引擎：引擎维护一个「当前游标」（复用定时器那套 `cursor`），翻页只移动游标 + 立即呈现，不重置定时器 |
| **滚动播报模式** | 一次把多条提示连续播出去，像跑马灯 / 字幕条：这条停 2 秒滑走，下一条滑进来，播完自动收 | 新增一个执行方式 `marquee`（注册进驱动桌面即可，引擎零改动）：`measure()` 返回更高的横条，`payload()` 一次带一批条目，由渲染层自己做滑动动画；驱动桌面的停留时长改为「整批播完」 |

这三条共用同一个前提：**动作包里的条目本身就是一句句独立的提示语**。所以数据格式不用改，只要在订阅包里把 `name` / `tags` 写清楚，关键词才命中得准。

### 8.2 AI 截屏识别：看懂当前场景，挑最合适的包

手动翻页和关键词仍然要人先动一下。更省事的是让它自己看：**截一张当前屏幕 → 让模型判断这是什么场景 → 在已订阅的动作包里挑最匹配的那一个 → 随机播报其中一条**。

流程大致是：

```
截屏（当前窗口 / 指定区域）
  → 把「动作包目录」一起给模型：每个包的 id / name / description / 条目 tag 汇总
  → 模型返回 { packId, 命中理由, 建议条目 }
  → 引擎按 packId 过滤候选，在该包内随机取一条 → 驱动桌面呈现
```

要点：

- **候选只用目录，不用全量正文**。几十个包也只传摘要，避免上下文被撑爆；模型选定包之后再在本地取条目，省 token 也省延迟。
- **随机播报**发生在「包已选定」之后，所以不会每次都推同一条，也不会因为模型输出不稳定而乱跳包。
- **可以挂在触发点上**：既可以是快捷键手动「看一眼我现在在干嘛」，也可以是定时器每次到点时先截屏判断一次。
- **隐私默认关闭**。截屏内容会上传到模型服务，所以必须是一个显式的开关 + 明确的提示（「只在你按下时截图，不上传视频流」），并且提供「只在本地跑 OCR、不外传」的降级路径。
- 这条能力依赖「执行方式」的扩展性：AI 只是**选包和选条目**，最终还是交给已有的 `text` / 未来的 `marquee` 去呈现，所以呈现层不需要知道 AI 的存在。
